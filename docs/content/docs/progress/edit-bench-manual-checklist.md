# 剪辑台「照着点」验证清单

这份清单给**独立剪辑台**（本轮新增：主时钟、吸附与导引线、拆分 / 删除 / 涟漪删除、快捷键表、撤销重做）用。

为什么需要它：这批交互**E1–E13 已全部由用户于 2026-09-25 手工确认通过**——用户整体表示「都测过了、没问题、全通过」，**没有逐条说明做了什么**，因此每一项的结论只覆盖「当时点上没问题」，不覆盖子步骤。**但手工通过不等于有回归保护：这些交互至今仍然完全没有自动化覆盖**，现存的自动化只有两类，覆盖不到交互本身：

- **单元测试**（纯函数 / store）：`web/src/lib/edit/timeline.test.ts`、`timeline-edit.test.ts`、`playback-clock.test.ts`、`shortcuts.test.ts`、`history.test.ts`、`web/src/stores/use-edit-store.test.ts`、`web/src/components/canvas/canvas-composite-panel.test.tsx`（连播切换部分）。
- **产物读回**（`renderToStaticMarkup` 静态渲染后读回 HTML 断言）：`web/src/pages/editor/editor.test.tsx`、`editor-timeline-ui.test.tsx`、`send-to-editor.test.tsx`、`canvas-composite-panel.test.tsx`（标尺 / 播放头渲染部分）。

真实指针拖动、真实按键、真实播放、真实文件选择器、真实 FFmpeg，这五条路径**完全没有自动化覆盖**。

2026-09-25 之后又修了一个真机缺陷：**暂停态预览区黑屏**（提交 `482aec5`，含暂停态 scrub 取帧，以及顺带修掉的「加载途中暂停会后台自动播放并出声」）。用户仍然只给了整体结论（原话「验过了 这次完美」，**未逐条记录子步骤**），**它同样没有拿到任何自动化回归保护**——见文末清单第 1 条与记录表的「E1 补充」行。

此后本轮又交付了四项**新内容 / 新修复**，并**全部由用户于 2026-09-25 真机确认「没问题」**（整体确认，**未逐条记录子步骤**）：**E14 音频波形**（新功能）、**E15 时间轴累积偏移修复**、**E16 音轨滚动条吃掉轨道宽度修复**，以及 **E17「我的画布」项目卡片操作按钮可见性**。E14–E16 是剪辑台本体，**E17 属于「我的画布」而不是剪辑台**，作为清晰标注的**补充条目**记在本清单里（本文件的 E1–E13 只覆盖剪辑台）。**E18 属于 Agent 后端（API 模式的 Skill 注入与「Agent 后端」开关），同样不是剪辑台**，也按清晰标注的补充条目记入。E18 的确认方式与前四项不同：用户**按步骤操作并给出了明确的现象级结果**，不是一句「没问题」的整体确认；但它**只走了「点选技能 + API 后端」一条通路**——`$技能名` 点名、Codex 后端、手动选择的后端不被自动拨回、日志里的注入数字**这四项都还没有人验过**（见 E18 与文末清单第 14 条）。

这四项——以及本次增记的 **E18**——同样**只覆盖「当时点上没问题」**，其中**真实素材的波形形状与解码耗时、真实 WebView 里滚动条究竟占多少像素、真实浏览器里按钮的观感与点击链路，仍然完全没有自动化覆盖**（见文末清单第 11–14 条；其中 **E18 是这批条目里自动化覆盖最薄的：一条测试都没有**）。本轮还沉淀了两条反过来会骗人的教训，已写进 E15 / E16 与 `AGENTS.md`：

- **只断言「末尾对齐」永远发现不了累积偏移**——修复前最后一段的右边缘本来就是准的（末端把 `gap` 预算补了回来），错的是中间各段的边与内部宽度，断言必须**逐段比对两条边**（见 E15）。
- **百分比断言抓不到「某一秒落在哪个像素」的问题**——滚动条扣宽度时波形条同样是满宽百分比、「右端对齐」同样成立，断言必须落在**像素与结构**上，并按多个时刻比对（见 E16）。

E14–E18 的表格在原「状态 / 前置 / 步骤 / 预期 / 怀疑」之外多一行**「自动化覆盖」**，用来逐项写清这套文档最看重的事：**它到底有没有回归保护、是哪一种保护**（**E18** 另加一行**「仍未验证」**，因为那次手工确认只走了两条通路里的一条）。其「步骤」行是把该功能**重新点一遍用的脚本**，**不是用户当时实际执行过的记录**（用户只给了整体结论）——**E18 是唯一例外**：它的「步骤」行里 ①②③④ 就是用户这次实际执行过的操作（⑤⑥⑦ 已标明「未执行」）。

后续怎么补自动化（建议方向）：① 把「松手才生效」做成用例——拖动过程只允许改 DOM、`pointerup` 才提交，用合成指针事件断言拖动中项目数据逐字未变；② 吸附解析（阈值换算、优先级、快拖抑制）继续以纯函数边界用例覆盖，补上极端缩放与越界夹取；③ 用桩时钟（假的 `AudioContext`）跑长片对齐与合成面板连播；④ 导出用一段固定短素材，在 CI 里跑一次真实 FFmpeg 冒烟并读回产物的时长与音轨；⑤ 主题对比度与导引线可见性用取色断言替代肉眼检查；⑥ 波形把现有的「现场生成 WAV」冒烟扩到一条真实素材（mp3 / m4a），并在 CI 里跑一次；⑦ 时间轴对齐的新断言**一律逐段比对两条边、一律落在像素上**——只断言末尾对齐或只看百分比，都会让 E15 / E16 这类缺陷再次溜过去；⑧ **Agent 后端那条路径（E18）现在一条测试都没有**，而它的注入逻辑是纯字符串拼装、不需要真机也不需要界面：把「skill 目录拼装与 6000 字符上限（超限丢弃哪些、丢几个）」「选中的技能才注入正文」「目录读不到时降级为无 Skill」做成对 `canvas-agent` 的单元测试，是这份清单里最容易补、也最该补的一条。
