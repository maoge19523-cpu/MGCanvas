# Pending Tests

The current release needs manual verification in these areas:

- Video composition node (desktop only): compose multiple connected video segments with optional background music via a user-provided local FFmpeg (auto-detect plus a manual path in Settings); verify per-segment in/out points, volumes, fades, resolution, mixed audio, and the generated video result node.
- ComfyUI 整合包引导：主 README 与模块 README 应展示ComfyUI 纯净整合包链接及「无模型、包含启动器」说明；使用整合包导入 API Format JSON、暴露输入输出并添加到画布的流程待实际环境验收。
- GitHub 展示：README 产品截图应正常加载，包含桌面项目管理、多素材创作全景、深色与浅色示例画布及 API 接入页；示例节点与实际创作截图的说明应清晰区分。

- 存储清理：仅使用 MGCanvas 数据库与存储键，验证画布状态、图片及媒体的保存、刷新恢复和删除；不再自动读取或迁移旧项目数据。

- 文档品牌清理：README 末尾仅保留一句二次开发来源说明，CLA 项目名称及中英文文档链接统一指向 MGCanvas；LICENSE 文件保持不变。
- API 注册引导：设置弹窗及独立设置页应显示整行「注册 通用服务商 · 获取 API Key」主按钮与两步操作说明；检查深浅主题、窄窗口以及桌面系统浏览器跳转，已有密钥的保存和余额验证保持可用。README 顶部应直接提供注册、连接画布与二次开发引导；验收无需触发付费生成。
- Canvas Wireless Mode: the left-side Canvas Appearance panel should expose explicit Connection and Wireless choices, with no duplicate mode control in the bottom zoom toolbar. Wireless mode should hide handles and lines without deleting existing data. Set and Unset controls must only render and execute in Wireless mode; Connection mode hides both the action and Set status indicator without clearing persisted Set data. Successful generated or uploaded image, video, audio, and text nodes must remain private until the user selects Set; native generators and exposed ComfyUI inputs can then Get them wirelessly through the node-anchored result picker. Search, type filtering, thumbnails, ordering, individual removal, Unset cleanup, source-deletion cleanup, undo/redo, restart recovery, and switching back to connection mode must remain correct. Regenerating a source should update what the next downstream run reads but must never auto-trigger paid work.
- Smart node alignment: dragging one node or a multi-node selection near another visible node's left/center/right or top/center/bottom axes should show viewport-spanning horizontal or vertical guides and apply a light magnetic snap. The perceived snap range must stay stable across zoom levels; guides must disappear after release, cancellation, or window blur, and smart alignment should take priority when grid snapping is also enabled.
- ComfyUI Local Mode: verify native selection, Python fallback, background start/stop, exit cleanup, logs, and restart recovery with Windows portable, source venv, and macOS venv installs. ComfyUI must bind only a random `127.0.0.1` port, never open its browser, and reject unauthorized profile IDs or dangerous extra arguments. Importing API-format JSON should run the five-step wizard against the live `/object_info`, allow explicit naming and selection of inputs/outputs, save missing-dependency drafts, and create a canvas macro with its complete snapshot, defaults, and named text/image/video/audio ports. Reverse dragging, compatibility, occupied inputs, output routing, and legacy handles must remain correct. Real execution should upload local inputs, call `/prompt`, expose running/stop state, parse `/history`, and fill reusable native image, video, audio, or text result nodes.
- The Windows desktop window should use the custom MGCanvas title bar integrated with the canvas, including drag regions, double-click maximize, minimize, maximize/restore, close, keyboard focus, a clear red close-hover state, and live light/dark theme sync without a white startup flash. macOS should retain its native traffic-light controls.
- The Tauri 2 desktop client should show the lightweight MGCanvas splash animation first, reveal the real canvas after local project hydration, and still reveal the main window after the native timeout if frontend startup fails. Windows file drag-and-drop, native Save As, hash-based deep navigation, Generic calls, and AppLocalData media playback must work without a browser or Vite server.
- `npm run desktop:package` should offer Windows, macOS, and all targets. Windows must create an NSIS `.exe`; macOS must create a universal Intel/Apple Silicon `.app` and `.dmg`; all must dispatch the two native GitHub Actions runners rather than claiming to build a DMG on Windows.
- Opening `/` should create or open the most recent MGCanvas project and enter the real canvas without showing the former marketing homepage; `/image` and `/video` and their Agent workbench tools should no longer exist.
- The canvas background should show subtle drifting light, a breathing grid, and pointer response without reducing node readability or changing pan, zoom, selection, drag-and-drop, or reduced-motion behavior.
- Image and video nodes should offer upload and generation from the empty state, show connected references in the attached composer, and infer text/reference generation automatically. The image footer should follow provider/model → ratio/resolution → output count → price/submit, with no More or advanced-parameter entry. Image geometry must be preset-only: no free-form ratio, width, or height input. Seedream/Dola presets must atomically derive model-specific width and height without also submitting the overriding `resolution`; the verified Generic GPT image ratios and 1k/2k/4k rules must remain model-aware; editable output counts must follow each documented model limit; fixed-count models must split 1–4x into independent single-result tasks without sending an undocumented count in any API request; and Midjourney must expose only ratio, speed, HD, and its independent 1–40 count mapping. References should disconnect only their selected edge, and completed media should fit its natural aspect ratio without blank bands or stretching.
- Generic Image G-2 must stay pinned to the documented `1k` contract and the three explicitly exemplified ratios. It must neither show nor submit the quality, `2k`, or `4k` fields found only on RHTV's direct model, and model migration must remove those stale fields.
- Node downloads must enter the browser's download list directly without opening a page or tab. Stable disk-cache URLs should be read directly; historical public HTTPS URLs should first be backfilled to `data/media-cache`, then fall back to the IndexedDB Blob behind a valid `storageKey`, direct browser reading, and finally the controlled same-origin download relay. Data or Blob URLs must be converted into a Blob before saving. A damaged or disabled IndexedDB copy must never block a healthy disk URL; 404s, empty or expired files, non-HTTPS relay targets, and local/private-network targets must show an error without navigating.
- A fresh profile should contain no preset provider endpoint, channel, model, prompt source, WebDAV directory, documentation URL, plugin registry, or remote release URL; all related screens should remain usable while empty.
- MGCanvas branding, `mgcanvas` storage/export markers, MGCanvas Agent/MCP names, and local plugin SDK identifiers should remain internally consistent after refresh, import/export, and local Agent startup.
- Async-task channel and task-node coverage: 55 documented operations, the verified 123 media models plus Kimi/Whisper/Suno, exact connected-resource and task-index placeholders, typed locally persisted result nodes, multipart proxy uploads, immediate Task-ID recovery journal, partial batch success, Midjourney `MODAL`, and stop/resume polling semantics.
- Paid Generic generation remains a manual acceptance item. Automated checks use official fixtures and the two free live action registries only; run minimum real image, video, Seed Audio, Kimi, Whisper, Midjourney, and Suno calls only after a test key and explicit cost authorization are provided.
- English and Simplified Chinese switching across navigation, settings, titles, descriptions, Ant Design components, and persisted preferences.
- Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability, prompt scrolling, generated-prompt restoration, image editing, drag-and-drop references, and generation configuration.
- Ordinary canvas nodes must stay within the 220×160 to 1600×1200 resize bounds. Aspect-locked media must never exceed the maximum bounds and must preserve its ratio when an extreme aspect ratio cannot satisfy both minimum axes. The opposite-corner anchor must remain fixed. Model, ratio, count, settings, and @-reference popups must remain attached to their node while the node moves or resizes and while the canvas pans or zooms.
- The image ratio popup should match the verified RHTV structure: a tall Auto tile on the left, a four-column ratio grid on the right, and equal-width resolution segments below, without changing each model's supported presets.
- Crop, split, and local upscale must work for both uploaded images and AI results backed only by a remote CDN URL. The editor should resolve a local Blob first, use the guarded same-origin relay when browser CORS blocks the source, and release temporary object URLs on both success and failure.
- Connections touching a running or polling generation node should show a restrained directional flow, return to normal at every terminal state, and become a static highlight under reduced-motion preferences.
- Successful Generic image, video, audio, and file outputs must be written to the repository's `data/media-cache` directory before the node receives its stable same-origin URL. With the remote CDN unavailable, refresh, crop, split, download, and downstream-reference flows must continue to work. Disk-cache failures must not be described as successful disk persistence or imply a browser copy when both layers failed; media files plus video Range serving must survive a development-server restart.
- When the first validated public IP for a CDN host refuses the connection and a later validated IP succeeds, both disk caching and the legacy download relay must fail over without weakening TLS, SNI, redirect, DNS-rebinding, or SSRF checks.
- Canvas Agent startup, MCP status, model and permission controls, approvals, version reporting, diagnostics, streaming responses, history consistency, multi-tab isolation, and local Skill management.
- Agent header tabs in English and Chinese at different panel widths; labels should collapse to icons and counts before either edge is clipped.
- Agent message layout, Markdown, code blocks, attachments, token statistics, progress timelines, command groups, and scroll-follow behavior.
- Prompt Center layout, custom-source synchronization, search, asset insertion, and prompt detail dialogs.
- Settings import/export from an initially empty configuration, Volcengine Ark protocol handling without an injected endpoint, and WebDAV-related configuration.

## 本地示例工作流与错误提示

- 本地内置示例工作流已更换为 Z-Image Turbo 基础文生图（与本地 ComfyUI 默认工作流一致），需重新点一次「安装示例工作流」覆盖旧示例。
- 运行工作流报「环境与工作流关联环境不一致」的问题已修复，更换过 ComfyUI 目录的工作流可直接运行。
- 模型不存在时（HTTP 400）错误提示已中文化：会指出哪个节点缺少哪个模型，并列出环境里可用的模型。
- 本地与云端的「刷新状态」现在会报告真实结果：本地提示 ComfyUI 是否启动成功（含地址），云端提示连接是否正常。
- 本地工作流「添加到画布」需在本机 ComfyUI 启动成功后才可点击。
- 参数面板已暴露模型类参数（模型 / LoRA / VAE / 文本编码器），模型缺失时可直接在面板里换成环境里已有的模型。
- 重新安装示例工作流时会自动清理同名与历史版本的旧示例，避免列表里残留引用旧模型的示例而被误点。
- 旧版内置示例「示例：基础文生图」会在本机环境就绪时自动就地升级为 Z-Image Turbo 版本（保留原工作流 ID，画布上已引用的节点同时生效）。
- 工作流参数面板不再显示大模型 / VAE / 文本编码器 / LoRA / ControlNet 等技术参数。
- 图片比例换算修复：以最后手动编辑的那一边为锚点，只调整另一边（例：宽度 768 点 16:9 得到 768×432）。
- 「ComfyUI 本地」页的本地工作流区恢复「安装示例工作流」入口，并统一走示例清单（此前残留实现仍指向已废弃的示例文件路径）。
- 本地与云端的示例工作流已分开：本地页只显示本地工作流，云端页只显示云端工作流；首页不再展示示例入口。

- 云端页状态区排版整理（标签在上、值在下，长地址截断显示）。
- 修复云端页在未连接云端时会装成本地示例：示例安装现在按调用方场景区分，云端未连接时提示「请先填写云端地址并点击连接」。
