# 待测试

- 内置语音脚本：用百炼渠道（模型 `qwen-tts`）或智谱渠道（模型 `cogtts`）生成一段音频，不写任何脚本也应成功，因为内置脚本是按接口地址命中的。百炼返回的是带签名的临时音频地址，必须仍能播放；智谱直接返回音频二进制，不得被文本解码破坏。面板上的「音色」必须真的进入请求；用方舟生成语音时应报出明确原因，而不是静默无声。

- 片段淡入淡出与音轨循环：片段自身的淡入/淡出应当只压低该片段首尾的画面与它自己的原声，同一接缝上设的转场仍应正常播放。给音乐轨打开「循环」后，短于成片的音轨应循环补齐到成片结束，其淡出仍以成片结尾为基准计算。

- 合成时间线：合成面板下方的时间轴应按真实时长排布每个片段，设了转场的片段标为菱形、硬切标为竖线，点击应跳回画布上对应的源片段。左右拖动片段本体应改变片段顺序，成片顺序随之改变；拖动片段两端应按片段宽度等比例调整该段的入点或出点，且不得越过另一侧边界；原有的「上移/下移」按钮与「入/出」输入框仍应编辑同一份设置。时间轴拖动现在改为松手才落盘，不再每次指针移动都写入：拖动片段本体时顺序不会实时变化，拖动端点时秒数也不会实时变化——两者都应在松开指针后一次性生效，并且拖动不再把界面拖崩。

- 风格馆封面：在画布左侧面板打开「提示词库」，点开任意风格，用「复制提示词」旁的「设为封面」为该风格挑一张本机图片；风格卡应立即显示这张封面，并在重启客户端后仍然保留。挑完风格后紧接着生成一张图，也应自动把该风格卡封面设为这张图（手动设过的封面优先）。只有内置风格显示这个按钮。

- 内置风格馆：提示词库应列出一个内置的「风格馆」来源，含 94 条原创风格描述，分真人写真、东方古风、现代影像、科幻幻想、自然氛围、暗黑废墟、巨物传说、二次元插画八类。按分类筛选、搜索、点选风格卡都应能填入提示词框。不联网也必须可用，并且在本版本之前就已经存过提示词来源的用户那里也应照常出现。

- ComfyUI 实时节点进度：在画布上运行 ComfyUI 工作流节点时，节点头部应显示当前正在执行的节点与步进百分比（形如「运行中 · KSampler · 60%」），并随执行推进更换节点名。运行结束后进度应让位给原来的「成功」结果与耗时。若进度始终不出现但运行正常完成，功能本身不受影响——请照实反馈，以便排查 WebSocket 通路。

- ComfyUI 运行历史：「ComfyUI 本地」页的工作流库下方应出现「运行历史」区。在画布上运行一次 ComfyUI 工作流节点应新增一条记录，含成败、开始时间、耗时与输出（图片显示缩略图）；失败的一次应显示错误原文；「删除」应只删一条、「清空」应全部删掉；重启客户端后记录应仍在。

- 时间轴拖动崩溃：在打包好的桌面版上，左右拖动片段本体或拖动任一端点都不得把界面拖崩。若界面确实弹出了错误卡，卡上应显示 React 报错原文、组件栈，以及崩溃前抓到的控制台输出；「重试」与「重新加载界面」都应能恢复。

- 百炼图生视频：给视频节点一张首帧图后生成的片段应跟随该首帧；纯文本运行仍保持已验证的文生视频形状。两种请求形状都已在真实接口上验证（图生视频任务跑到 SUCCEEDED 并返回了 `video_url`），因此剩下要确认的只是从画布图片到视频节点的应用内链路。

- 302.AI 渠道：它只能经本机系统代理访问（直连其海外节点会超时），因此按新增的 `https://api.302.ai/v1` 预设添加渠道并点「获取模型」后，应当返回模型列表或服务商自己的原话——若返回网络超时，就说明桌面端 HTTP 层没有跟随 Windows 代理设置、需要单独处理。该渠道的对话与图像生成应无需任何调用脚本即可使用；视频与音频要先按其真实请求形状核对，再决定是否写脚本。

- 百炼视频尺寸：视频调用脚本必须发送服务端接受的尺寸之一（1080*1920、1920*1080、1440*1440、1632*1248、1248*1632、480*832、832*480、624*624）——此前的取值会让每个任务都以 `InvalidParameter` 失败（已实测），而 `1920*1080` 轮询到 SUCCEEDED 并返回了 `video_url`。因此通过百炼渠道生成视频时，画布上每个画幅都应能出片并正常播放。

- 智谱按模型使用各自的画幅尺寸：图片调用脚本必须按模型选择画布尺寸，因为 `glm-image` 只接受能被 32 整除的边长——用于 16:9 的 CogView 尺寸（`1440x720`）会被拒并返回 1214（已实测），而 `1728x960` 可以通过。因此把渠道的图像模型选为 `glm-image` 后，面板里提供的每个画幅都应仍能出图。

- 渠道文本端点：通过渠道模型发起的文本生成——包括节点提示词面板、配置节点的内容面板与节点重试——都应请求 `{base}/chat/completions`，并把回答流式写入节点。智谱在 `/responses` 上返回 404（已用真实 Key 实测）、在 `/chat/completions` 上返回 200；只带 `role` 的首个分片应被跳过；智谱与 DeepSeek 都会随正文一起返回的 `reasoning_content` 字段绝不能漏进节点文字。忽略流式、直接整段返回一个 JSON 的服务商也应能正常填入节点；思考强度必须按标准的 `reasoning_effort` 字段发送，而不是 Responses API 的 `reasoning` 对象。

- 渠道视频请求体：没有匹配调用脚本的渠道模型必须发送标准 OpenAI videos 形状——`model`、`prompt`、`seconds`、`size`、`input_reference[]`——不得带 `resolution_name` 或 `preset`；严格兼容的服务商应能接受该请求，面板上选的分辨率仍应作为 `size` 发出。

- AI 导演整片交接：「一键生成整片」完成后，生成的成片下方应已经接好一个合成节点，加音乐与整片裁剪不需要再手动建节点、连线；随后应弹出审片提示，复述本次要求的总时长与画幅，以及生成时规范自检报出了几个问题。

- AI 导演整片打包密度：发给推理模型的系统提示词必须带上本次时长对应的具体镜头数——10 秒 2–3 镜、12 秒 3–4 镜、15 秒 3–5 镜——并连同总时长与画幅一起给出，还要明确要求模型不要反问用户要几个镜头。规范自检必须使用同一份数字，因此 15 秒却只切成两个镜头时应报密度提醒、切成三个镜头则不应报；对 Seedance 永远不应触发该提醒，因为它的镜头块是在自己那一条提示词内部计数的。

- 对比节点分割线：接上两张图片后，把指针移到分割线上就应能左右拖动分割位置，不需要按住任何修饰键；在图片上任意位置按下左键也应能拖动——节点内与全屏视图里都一样。分割线上的把手胶囊必须真的能抓住，而不是画上去的装饰。打开全屏对比后点 ✕ 应能关闭；画布内打开的其它 antd 弹窗，其关闭按钮也不得被画布平移吞掉。

- 画布缩略图缓存：节点在屏幕上占用的像素不超过 1024 设备像素时，图片节点应渲染缩小后的 webp 而不是原图，缩放把它推过这个阈值后应立即回退到原图。打开一个约有 50 张大图的画布，第二次进入应明显快于第一次，因为缩略图是从 IndexedDB 取回而不是重新编码。缩略图绝不能混进下载、导出、已保存的拼图或任何发给模型的内容。缓存必须是有界的：30 天未使用的条目会被清除，存储按最近最少使用顺序压缩回 400 条 / 80 MB。远程图片污染画布时应静默回退到原图，而不是显示破图。

- ComfyUI 本地运行环境摘要：ComfyUI 跑起来之后，环境面板应显示本机显卡及其空闲/总显存，以及本地已安装模型的计数，按 Checkpoints、diffusion 模型、文本编码器、VAE、LoRA 分组。两个值都来自 ComfyUI 自己的 `system_stats` 与 `object_info`，因此 ComfyUI 未运行时应保持为空，点刷新按钮后才更新。没有任何模型文件的机器应显示 `No model files detected`，而不是一排 0。

- ComfyUI 启动进度：进度条应依次经过检查环境、启动进程、加载自定义节点与模型、等待 Web UI 几个阶段，且在自定义节点还在加载时不得提前走满。加载阶段应带上提示：首次启动或节点很多时，这一步最慢。连接云端 ComfyUI 时，该操作的文案应写成「断开连接」而不是「停止」，因为不涉及本地进程。

- ComfyUI 本地工作流依赖诊断：工作流库标题应显示 `N / M 个工作流可用`，每个不可用的工作流都要同时列出缺失的节点 `class_type` 与缺失的模型文件。导入 API 工作流时，缺失模型应与缺失的 `class_type` 并排列出。某个工作流的 checkpoint、LoRA 或 VAE 在正在运行的 ComfyUI 里不存在时，应在工作流库与它的画布节点上都算作不可用；而采样器、调度器这类普通枚举值绝不能报成缺失模型。

- 测试版构建渠道：`npm run desktop:build:beta` 应产出使用独立标识符 `com.mgcanvas.app.beta` 与独立可执行文件名 `mgcanvas-beta.exe` 的 `猫歌映画 测试版` NSIS 安装包，因此安装或升级测试版永远不会关掉正在运行的正式版。它应与正式版并存安装，并以空工作区启动，不影响正式版的项目与设置。测试版主窗口标题应为 `猫歌映画 测试版`；正式版 `npm run desktop:build` 的标识符、`mgcanvas.exe` 文件名与 `猫歌映画` 标题都应保持不变。

- ComfyUI 整合包引导：主 README 与模块 README 应展示ComfyUI 纯净整合包链接及「无模型、包含启动器」说明；使用整合包导入 API Format JSON、暴露输入输出并添加到画布的流程待实际环境验收。
- GitHub 展示：README 产品截图应正常加载，包含桌面项目管理、多素材创作全景、深色与浅色示例画布及 API 接入页；示例节点与实际创作截图的说明应清晰区分。

- 存储清理：仅使用 MGCanvas 数据库与存储键，验证画布状态、图片及媒体的保存、刷新恢复和删除；不再自动读取或迁移旧项目数据。

- 文档品牌清理：README 末尾仅保留一句二次开发来源说明，CLA 项目名称及中英文文档链接统一指向 MGCanvas；LICENSE 文件保持不变。
- API 注册引导：设置弹窗及独立设置页应显示整行「注册 通用服务商 · 获取 API Key」主按钮与两步操作说明；检查深浅主题、窄窗口以及桌面系统浏览器跳转，已有密钥的保存和余额验证保持可用。README 顶部应直接提供注册、连接画布与二次开发引导；验收无需触发付费生成。

- 画布无线模式：左侧“画布外观”面板应提供“连线模式 / 无线模式”供用户明确选择，底部缩放控制区不再重复展示；切换无线模式后隐藏端口和连线但不删除既有数据。“设为 Set / 取消 Set”只允许在无线模式显示和执行，切回连线模式后入口与 Set 状态图标均隐藏，但既有 Set 数据不清除。生成或上传成功的图片、视频、音频与文本节点只有在用户点击“设为 Set”后才进入全局引用列表，其他原生节点和 ComfyUI 暴露输入可通过跟随节点定位的“引用结果”选择器无线 Get。候选搜索、类型过滤、缩略图、排序、单项移除、取消 Set、来源删除清理、撤销重做、项目重启恢复以及切回连线模式均应正常；取消 Set 时应移除已有无线引用，来源再次生成后下游下一次运行读取最新成功结果，但不得自动触发付费任务。
- 节点智能对齐：拖动单个节点或多选节点组接近其他可见节点的左/中/右、上/中/下基准轴时，应出现覆盖当前视口的水平或垂直参考线并轻微磁吸；缩放后视觉吸附距离应保持稳定，松手、取消或窗口失焦后参考线必须消失，开启网格吸附时智能对齐优先。
- ComfyUI 本地模式：在 Windows portable、源码 venv 与 macOS venv 环境中分别验证原生目录选择、Python 回退选择、后台启动、停止、退出清理、日志和重启恢复；启动不得打开 ComfyUI 浏览器，只能绑定 `127.0.0.1` 随机端口，未授权环境 ID 与危险附加参数必须被拒绝。导入 API Format JSON 后，五步向导应按当前 `/object_info` 显示真实依赖，可自由勾选并命名输入/输出、保存缺依赖草稿及可运行工作流；加入画布后宏节点应保留完整快照、参数默认值和文本/图片/视频/音频等具名端口。反向拖线仍保持源到目标方向，不兼容或已占用输入端口拒绝连接，不同输出端口把各自资源传给下游，同时旧节点连接点和工作流保持不变。实际提交应能上传本地输入、调用 `/prompt`、显示运行/停止状态、解析 `/history`，并把图片、视频、音频或文本写入可复用的原生结果节点。
- 桌面窗口栏：Windows 主窗口应显示与画布融合的 MGCanvas 自定义深色标题栏，支持空白区域拖动、双击最大化、最小化、最大化/还原、关闭和键盘焦点，关闭悬停为明确红色危险态；切换 MGCanvas 明暗主题时标题栏同步变化，启动不得闪白。macOS 继续显示原生交通灯按钮。
- Tauri 2 桌面客户端：启动时应先显示轻量 MGCanvas Loading 动画，本地项目恢复并绘制首帧后再进入真实画布；若前端初始化异常，原生超时兜底也必须显示主窗口。Windows 文件拖放、原生“另存为”、Hash 深层路由、通用调用与系统应用目录媒体播放均应在不启动浏览器或 Vite 服务的情况下工作。
- 桌面打包脚本：运行 `npm run desktop:package` 应可选择 Windows、macOS 或全部；Windows 生成 NSIS `.exe`，Mac 生成 Intel/Apple Silicon 通用 `.app/.dmg`，“全部”必须调度 Windows 与 macOS 两个 GitHub Actions 构建机，不得在 Windows 上伪装生成 DMG。
- 首页直达画布：访问 `/` 后应自动创建或打开最近使用的 MGCanvas 项目并进入真实画布，不再展示原宣传首页；`/image`、`/video` 及对应 Agent 工作台工具均应不存在。
- 画布灵动背景：深色与浅色主题下应显示低干扰的流动环境光、呼吸网格和指针响应，节点可读性以及平移、缩放、框选、拖放均不受影响；系统开启“减少动态效果”后应停止持续动画。
- 图片与视频节点：空节点应能直接上传或在下方配置生成；连接图片、视频、音频或文本后，下方创作面板应立即显示真实参考缩略图并自动切换文生图、参考生图、文生视频或图生视频，不出现需要手选的“模型能力”；图片底栏应按“厂商/模型版本 → 比例/分辨率 → 生成数量 → 价格/生成”排列，不显示“更多操作”或高级参数入口；所有图片比例均只能从当前模型预设中选择，不能手填比例、宽度或高度；需要显式宽高的 Seedream / Dola 模型应按模型级尺寸表原子填写宽高且不得同时提交会覆盖宽高的 `resolution`；通用GPT 低价图片应提供已核实的比例与 1k/2k/4k 选择，4k 仅允许对应的四个宽幅比例；Qwen、GK、NB 等模型仅显示其文档确认的数量范围，固定数量模型应将 1–4x 拆成独立的单结果任务，且每个 API 请求不得携带未文档化的数量字段；Midjourney 仅显示比例、生成速度、HD 和独立数量，其中 1x 不发送 `repeat`、2–40x 正确发送，旧高级字段切换模型后应清理。删除缩略图仅断开对应连线；生成完成后节点应按真实宽高比调整并保持中心，图片和视频均填满预览且不出现透明空带、黑边或拉伸变形。
- Generic Image G-2：参数应固定为官方文档开放的 `1k` 与三个已明确举例的比例，不显示或提交 RHTV 直连模型才有的图像质量、`2k`、`4k`；从旧节点或其他模型切换时也应清理这些遗留字段。
- 节点下载：图片、视频、音频与普通文件点击下载后应直接进入浏览器下载列表，不打开新页面或新标签；稳定磁盘地址应直接读取，历史公开 HTTPS 地址应先补写到 `data/media-cache`，失败后再依次回退 IndexedDB、副本直读和受控同源下载中转；Data URL 与 Blob URL 应先转换为 Blob。IndexedDB 被禁用、损坏或返回空文件时不得阻断健康的磁盘地址；404、空文件、过期地址、非 HTTPS 中转目标及本机/内网目标应显示明确错误且不得跳转。
- 空白配置：全新浏览器配置中不应预置服务地址、渠道、模型、提示词来源、WebDAV 目录、文档地址、插件注册表或远程版本地址；空状态下配置、画布和插件界面不得发起无效请求或崩溃。
- MGCanvas 品牌一致性：页面标题、导出标识、`mgcanvas` 持久化键、MGCanvas Agent/MCP 与本地插件 SDK 命名应一致，刷新、导入导出和本地 Agent 启动后不应再暴露原项目品牌入口。
- 通用渠道与任务节点：新增 通用渠道时不应请求不存在的 `/v1/models`，模型选择应来自已核对的 123 个媒体模型及 Kimi、Whisper、Suno 目录；画布工具栏和连线创建菜单应能创建「通用生成任务」，面板应列出通用 8 项、Midjourney 16 项、Suno 31 项共 55 项操作，并能切换官方模型、渠道和 JSON 参数。
- 通用素材与结果映射：连接文本、图片、视频、音频及上游 通用任务后，`@Text N`、`@Image N`、`@Video N`、`@Audio N`、`@Task N`、`@TaskAudioIndex N`、`@TaskIndex N` 和 `@TaskZeroIndex N` 应严格按序解析，较长提示词内的同名片段不得被替换；本地 Blob 素材应通过同源代理上传，完成媒体应立即转存到本地持久存储并分别展开为图片、视频、音频、文本或文件结果节点，多首 Suno 曲目及 Midjourney U1–U4 索引不得互相错位，Task ID、宫格图和 buttons 应保留在任务元数据中。
- 异步任务状态：提交后应同步写入即时恢复日志并保存全部 Task ID、远端状态和进度；硬刷新、删除节点或点击「停止轮询」后应明确提示远端任务仍会执行且可能计费，并能恢复查询；批量任务部分失败时不得吞掉已成功并计费的结果。Midjourney `MODAL` 应停在等待补充参数状态，不得判为失败或无限轮询。官方没有取消接口，界面不得声称已取消远端任务。
- 通用真实计费验收：无 API Key 的自动测试只覆盖官方示例响应、错误、上传协议、轮询和两个实时免费 action registry，未调用任何计费生成接口；提供测试专用 Key 并明确授权费用后，仍需各执行一次图片、视频、Seed Audio、Kimi、Whisper、Midjourney 与 Suno 的最小真实任务，核对余额变化、媒体可访问性和任务恢复。
- 文档站国际化：访问文档站首页及 `/docs` 应默认显示英文，切换简体中文后 URL 应带 `/zh-CN` 且首页、顶部导航、侧边栏、正文、搜索框和页面操作文案均显示中文；刷新、站内跳转和再次切回 English 后语言应保持正确，搜索结果与 Markdown/LLM 文档内容不得混入另一种语言。
- 国际化基础框架：从页面右上角切换简体中文或 English 后，首页、顶部及移动端导航、版本弹窗、配置主面板、渠道编辑、模型选择、页面标题、页面描述和 Ant Design 内置文案应立即切换，刷新页面后保持所选语言；偏好设置中不应再显示语言选项，WebDAV 同步错误、提示词来源及其他尚未接入翻译的业务模块暂时仍可能显示中文。
- 全局弹层主题：全站 Dropdown、Menu、Select、Cascader、TreeSelect 等弹层在浅色主题下应使用白色背景、轻灰悬停和选中态，在深色主题下应使用深色背景与低对比度浅色交互态，不应再出现默认黑灰色块、文字对比不足或单个页面配色不一致。
- 画布节点缩放稳定性：选中任意节点并反复拖动四角缩放时，节点工具条应在缩放期间隐藏、松开后恢复，页面不应再出现 `Maximum update depth exceeded`。
- 画布节点尺寸与弹层跟随：普通节点四角缩放应限制在 220×160 至 1600×1200；图片、视频等锁定比例节点不得超过最大边界，并在比例与最小边界无法同时满足的极端宽高比下优先保持原比例。左上/右上/左下缩放时固定对侧锚点不漂移。打开节点模型、比例、数量、设置或 @素材候选弹层后，再移动节点、调整节点大小及缩放/平移画布，弹层应始终跟随对应节点并按画布比例同步变化，不固定在屏幕原位置，也不得越出可视区后无法操作。
- 图片比例弹层：比例区域应与 RHTV 一致采用左侧纵向“自适应”大卡、右侧四列比例网格以及底部分辨率等分按钮；项目当前模型的比例顺序、可用分辨率、选中态和禁用规则必须保持不变，弹层随节点及画布缩放时不应错位。
- AI 生成图编辑：对已转存和仅保留远程 CDN 地址的 AI 生成图片分别执行裁剪、切图和本地放大，均应生成新的本地图片节点；跨域直读失败时应自动使用受控同源中转，临时 Blob URL 在成功或失败后均应释放，错误时显示明确提示。上传图片的原有编辑行为应保持一致。
- 工作流运行连线：任一图片、视频、音频或文本节点进入生成、轮询状态时，与该节点相连的工作流线条应显示方向明确、连续且低干扰的流光；任务完成、失败或停止后立即恢复普通线条。系统启用“减少动态效果”时不得持续移动，只保留静态运行高亮。
- 生成结果磁盘缓存：通用图片、视频、音频和文件任务成功后，应先在仓库 `data/media-cache` 产生可直接使用的文件和 manifest，再将稳定同源 URL 写入节点；关闭远程 CDN 后刷新、裁剪、切图、下载和作为下游参考仍应成功。磁盘服务失败时不得误报已写磁盘；磁盘与浏览器副本均失败时也不得暗示已有浏览器缓存。开发服务重启后文件仍应可读，视频 Range 请求应返回 206。
- CDN 故障切换：模拟同域名首个公网 IP 返回 `ECONNREFUSED`、第二个公网 IP 成功时，磁盘缓存与旧下载代理均应自动切换并完成转存；每个地址仍需经过公网校验和固定连接，重定向到内网必须被拒绝。
- Agent MCP 初始化状态：首次进入空白对话、点击「新对话」或恢复历史对话后，无需先发送消息，对话区应立即显示 Codex 会话准备，并列出 `codex_apps`、`mgcanvas`、`node_repl` 等完整 MCP 服务状态；全部服务进入终态前可输入并保留草稿，但发送按钮、上传和回车提交应禁用；可选 MCP 失败时应提示警告但允许发送，`mgcanvas` 缺失或失败时应阻止发送并显示明确原因；首轮及后续任务运行期间再次收到的 MCP 状态只进入诊断日志，模型开始处理及回复完成后对话区不应残留初始化卡片。
- Agent 模型设置：连接 Canvas Agent 后，输入框左下方应显示当前 Codex 模型与推理强度；模型列表应来自当前账号实际可用模型且不显示内部审查模型或重复项，切换模型后强度选项随模型能力更新且无空白选项，刷新页面后保留选择，发送任务时实际使用所选模型和强度；本地控制台与右侧「日志」应记录本轮使用的模型和推理强度。
- Agent 新对话响应：一轮对话完成后点击「新对话」，聊天内容应在服务端确认切换后清空并进入空白对话；后台应串行创建线程并预热 MCP，多个标签页应按同一会话版本同步，旧 HTTP 响应不得覆盖较新的 SSE 状态，初始化完成前不能发送到上一条会话或重复创建线程；重启 Agent 后应重新恢复并预热已有活动线程，无法恢复的失效空线程应自动替换为可用的新线程。
- Agent 读取画布卡片：读取当前画布完成后，卡片应按非零类型显示文本、图片、配置、视频、音频、分组、其他节点及连线数量，例如「3 个文本、5 张图片、2 个配置、4 条连线」；空画布应显示「当前画布为空」，执行失败时仍应显示错误信息，刷新恢复历史后统计保持一致。
- Agent 首次发送响应：在空白新对话中输入内容并按回车后，输入框应立即清空、用户消息应立即出现在对话中，再显示「正在思考」；线程创建或发送失败时，原输入和附件应恢复；任务运行期间输入的新草稿不应在请求成功后被清空。
- Agent 动态工具信息：执行内置生图、查看图片、命令、文件修改或其他动态工具时，卡片标题应显示具体工具名称；执行失败时正文应显示真实错误原因，刷新并恢复历史对话后仍应保持一致，不再统一显示「工具操作已完成」。
- Agent 画布生图：重启 Canvas Agent 后，其自动生成的工作区 `AGENTS.md` 应同步为最新版指令（用户自行编写的其他 `AGENTS.md` 不应被覆盖）；输入“生成一张图片”时应调用 `canvas_generate_image`，通过当前画布节点创建并运行生成流程；只有明确输入“使用 Codex 内置生图/ImageGen 技能生成”时才允许调用内置能力，Codex App Server 返回的 `imageGeneration` 结果应显示在对话中并作为保持原比例的图片节点添加到当前画布；Agent 不应在没有生成结果时提前声称“已生成”。
- Agent 顶部栏：在对话、历史和日志之间新增「技能」标签并显示已加载数量；连接状态应位于左侧 Agent 标题旁，并与右侧新对话使用相同规格的文字按钮，只有内容标签显示选中线；标签图标始终显示，中英文模式下都应按标签区域的实际可用宽度隐藏文字并保留小号数量，空间足够时显示图标和文字，拖动宽度时不应裁切、换行、横向滚动或错位。
- Agent 输入框窄屏布局：底部上传、Skill、确认模式、权限模式、模型和思考程度控件在窄面板下应只显示图标，宽面板下恢复文字；所有纯图标操作悬停时应使用统一样式显示名称或当前状态，任意宽度都不出现横向溢出。
- Agent 本地 Skill 管理：连接 Canvas Agent 后进入「技能」，应能读取当前 Codex 工作空间发现的项目、个人、系统和管理员 Skill，并支持搜索、按范围筛选、刷新及启停；未能加载的 Skill 应通过可点击、可滚动的详情查看原因；画布在站点工作空间 `.agents/skills` 下创建的 Skill 应可新建、编辑和删除，其他来源只读且不得被画布改写；编辑期间文件被其他窗口修改时应拒绝覆盖，清空显示名称、短说明和默认提示词后旧值应被删除，同时保留图标、品牌色等未由当前界面管理的元数据；多个标签页同时连接时，任一页面的 Skill 变更应自动同步，断开或切换 Agent 时旧请求不得重新写回列表或弹出编辑器。
- Agent Skill 草稿生成：创建 Skill 时应提供「空白创建」「从当前对话生成草稿」「从当前画布生成草稿」三种入口；空对话不得发起生成，取消时不得写入文件，确认后才写入站点工作空间 `.agents/skills`；Agent 运行中应禁用生成，多标签页下对话和画布来源必须分别严格绑定发起请求的 `threadId` 和 `clientId`，生成期间外部 MCP 仍应操作最近聚焦页面；草稿运行时创建、启停、删除和更新 Skill 应被统一拒绝，点击停止应真实中断临时草稿 turn；草稿不得泄露本地路径、密钥、媒体数据、真实节点 ID 或任务进度等临时状态，普通中文斜杠文本与 `/imagine` 等命令必须保持完整，生成草稿使用的临时 turn 不得出现在 Agent 对话、历史或日志中。
- Agent Skill 调用：在技能页点击「使用」或在输入框左下方选择 Skill 后，输入框上方应显示可移除标签；发送任务时应通过 Codex 原生结构化 Skill 输入执行，而不是只把名称拼进普通提示词，发送成功后清除选择，失败时保留；新建对话、断开连接、Skill 被停用或删除时也应清除失效选择，发送前、任务完成后和刷新历史后的用户消息文字应保持一致。
- Agent Markdown 样式：右侧 Agent 回复中的代码块应为横向占满消息区域、无语言标题和无双层边框的紧凑代码条，单行内容不应保留纵向大面积空白，复制操作仅在悬停时弱化显示；行内代码、链接在浅色和深色主题下应清晰；点击外部链接后应显示中文紧凑确认弹窗，长路径能够正常换行且复制、继续打开和关闭操作可用；点击 `/Users/`、`/home/` 等本地绝对文件路径时应改为提示在系统文件管理器中定位，支持复制路径，且浏览器地址不应跳转为 localhost 文件路径。
- Agent 工具确认模式：右侧面板标题栏不应再显示「工具确认」开关；对话输入框左下方应显示确认模式选择，默认选中「自动确认」，画布写入工具应直接执行；切换为「手动确认」后，画布写入工具应在对话中展示等待确认卡片，并支持批准或拒绝。
- Canvas Agent Codex 升级：启动 Canvas Agent 后应输出 Canvas Agent、内置 Codex 和本机 Codex 版本，实际运行的内置 Codex 应为 0.146.0；内置与本机版本不一致、未安装本机 Codex，或 npm 存在更新版本时应显示对应升级提醒，npm 检查失败不应阻止服务启动；Agent 应能正常连接 Codex、创建或恢复会话、发送消息并调用画布工具，运行中停止任务应只中断当前 turn，随后无需重启 Agent 即可继续发送新任务。
- MGCanvas Agent Debug：普通启动应通过公共 logger 输出 Info、Warn 和 Error 日志；使用 `npm --prefix canvas-agent run debug` 启动后还应输出 Debug 日志并显示日志文件路径，终端统一采用“`YYYY-MM-DD HH:mm:ss` 级别 消息 详情”的纯文本单行格式，`~/.mgcanvas/logs/` 下应按启动日期生成相同格式的 `mgcanvas-YYYY-MM-DD.log`，同一天多次启动应追加到同一文件；日志中不应出现连接 token 或图片 Data URL 原文。
- Canvas Agent Codex 日志：Codex app-server 输出带颜色或样式控制符及 UTC 时间的 stderr 时，本地日志和网页诊断日志应只显示一份 `YYYY-MM-DD HH:mm:ss` 本地时间和干净文本，不应出现重复 ISO 时间或 `[2m`、`[31m` 等 ANSI 转义内容。
- Agent HTTP 诊断日志：网页发送一条普通消息后，本地 Debug 日志不应重复输出 `/health`、`/canvas/state`、`/canvas/activate` 成功请求、流式增量或完整会话响应，只保留 HTTP 请求与 Codex 生命周期摘要；右侧「日志」应以单行时间线展示发送、开始、回复、工具、完成用量和错误，不再输出 userMessage started/completed、流式摘要、重复 threadId 或大段原始 JSON。
- Agent 排查日志：右侧「日志」中的排查视图应显示连接摘要，并可按错误、警告和信息筛选；向下查看日志时仅列表内部滚动，标题、连接状态、筛选数量和操作按钮保持固定；连续相同事件应折叠计数，单条日志可展开查看完整详情；原始 JSON、复制全部、复制最近错误和清空功能应继续可用，浅色与深色主题下均应清晰。
- Agent 排查日志顺序与跟随：日志应按时间从旧到新排列，进入日志或切换筛选时定位到最新事件；停留底部时自动跟随新日志，展开最后一条后应继续停留在完整详情底部，向上浏览后暂停跟随并显示与对话区视觉高度一致的居中圆形向下箭头，新日志数量只在悬浮提示中显示；列表底部不应出现额外留白，点击按钮后回到底部并恢复跟随。
- Agent 对话统计：用户消息应右对齐并使用透明无气泡的简洁排版，用户和 Codex 两侧均不显示人物头像，消息下方均不显示时间或 Token 信息；输入框上方应居中展示最新一次模型调用的输入、缓存、输出 Token 用量，不显示会话累计值，数值更新时应从旧值平滑滚动到新值而非突然跳变，新建、切换或删除当前会话后应清空旧统计。
- Agent 回复实时显示：在右侧 Agent 发送消息后，用户消息下方应立即出现“正在思考...”，任务运行期间不应闪退；工具完成后应显示 Codex 正在继续处理及已等待时长，等待超过 30 秒时提示可继续等待或停止本轮；Codex 的回复应在当前对话中持续显示，实时事件缺失时也应在任务完成后自动同步完整内容，无需切换到历史或日志再返回对话。模型繁忙等任务失败时应立即结束等待状态，在对话中显示中文错误原因和重试建议，诊断日志不应再把失败轮次记为“处理完成”，刷新历史后错误仍应保留。新建尚未发送首条消息的空会话不应反复出现历史读取失败。
- Agent 对话实时与历史一致性：运行包含思考、命令及画布工具的较长任务，在执行中刷新发起页面或打开第二个页面时，已出现的用户消息、思考过程、工具卡和回复前缀均应保留并继续更新；同一思考或工具只显示一张卡片，任务结束及再次刷新后内容、顺序和状态应一致。切换页面焦点不能改变本轮画布工具目标，发起页面断开后不得把图片或写操作转交其他画布，使用相同页面身份重连后才能继续处理。
- Agent 流式交互性能：发送长回复时文字应连续平滑出现，输入框、滚动和画布操作不应随回复变长而明显卡顿；长历史会话中只有当前流式消息持续更新，屏幕外消息不应造成明显布局压力；任务完成后应通过 SSE 自动同步完整历史，不再持续请求 `/health` 轮询状态。
- Agent 过程时间线：新建 Agent 对话后 Codex 应生成可读思考摘要，并在运行时依次显示中文的思考摘要、执行计划、命令执行、网页搜索、文件修改和画布工具活动；思考摘要的图标、标题和箭头应稳定保持在同一行，默认收起且无边框，点击箭头后才展开 Codex 实际返回的具体摘要，其中 Markdown 强调、列表和代码应正确渲染而非显示原始符号，多行代码块和文本流程图应保留原始换行并允许横向滚动，完成事件不应再用「已完成分析」覆盖已经收到的摘要；同一轮连续命令应合并为显示数量的无边框折叠行，折叠时不显示命令预览，单条展开后直接显示详情，多条展开后可逐条查看工作目录、耗时、退出状态和运行输出；其他工具调用继续使用紧凑卡片排版，状态图标、标题和状态文字保持在同一行；结构化任务进度不应混在对话时间线中，而应独立放在对话区下方、Token 统计上方，支持展开和折叠，并逐项实时更新「待处理」「进行中」「已完成」状态；新任务生成时默认展开，任务结束后保留最新结果，同一计划更新不应生成重复内容；文件详情展示文件路径与新增/修改/删除动作，工具详情不应出现请求 ID、英文工具名或原始 JSON；一轮对话结束自动同步历史以及刷新页面后从历史中 resume 对话时，思考摘要、命令和工具过程记录仍应完整保留并保持相同展示。
- Agent 权限控制：输入框可选择「请求批准」「自动审查」「完全访问」；请求批准模式下，Codex 编辑工作区外文件、执行受限命令或访问网络时应在对话中显示审批卡片，支持拒绝、允许一次和本会话允许，并能依次处理多个并发请求；提交决定后卡片应保持禁用等待，只有 Codex 确认处理后才移除；等待审批时刷新页面，未处理的审批卡应自动恢复且不能让任务永久卡住；自动审查模式应仅将需要用户决定的风险操作送入审批；完全访问必须先显示风险确认，启用后可访问网络和本机文件且不再请求审批；选择应在刷新后保留。
- Agent 历史记录：点击记录卡片应直接进入对应对话，不再显示「进入」按钮；可勾选单条或全选多条记录并批量删除，删除当前对话后聊天内容应清空。
- Agent 默认新对话：每次进入任一画布并连接 Agent 后，对话区应保持空白且不自动恢复上一次会话，并在后台创建新线程、预热 MCP；需要继续旧对话时可在「历史」中主动选择恢复。
- Agent 当前画布优先：在已打开某个画布时要求 Agent 创建、修改、整理或生成内容，Agent 应直接读取并操作当前画布，不应先调用 `canvas_list_projects` 或使用 `site_navigate` 重复进入画布；只有明确要求查看或切换其他画布时才允许查询画布列表并导航。
- Agent 图片消息：发送一张或多张图片附件后，图片应紧跟用户文字并在消息右侧显示为约 40px 的紧凑缩略图，不再撑大消息区域，单击缩略图应打开大图预览，打开或关闭预览不应改变消息间距或产生额外空行；任务运行中、完成同步历史、切换页面及重新进入历史对话后都应显示浏览器本地保存的图片缩略图，不应消失或把 attachmentId、附件使用说明等内部上下文回显到用户消息中；删除历史会话后应同步清理对应缩略图。
- 画布文本复制：在 Agent 对话或节点信息详情中用鼠标选中文字后，按 `Ctrl/Cmd + C` 应复制所选文本，不应触发画布节点复制；未选中文字且焦点位于画布时，原有节点复制快捷键应保持可用。
- Agent 工作目录指令：`canvas-agent/agent-instructions.md` 应作为独立维护源；重启 MGCanvas Agent 后，当前工作目录应自动生成 `AGENTS.md`；新建对话发送消息时，Codex 日志中的用户消息只包含本轮请求和必要的附件上下文，不再重复整段 MGCanvas 前置提示词，画布工具仍可正常调用。
- 画布文本设置：文本节点和生成配置节点切换到文本模式后应显示推理强度设置，可选择自动、低、中、高、极高；选择自动时默认 OpenAI Responses 请求不应携带 `reasoning`，选择其他档位时应携带所选强度，刷新画布后节点设置应保留；文本模型自定义调用脚本应能读取 `reasoningEffort`，OpenAI 模板应按自动或指定档位正确组装请求。
- 画布组装提示词：输入或连接超长提示词后，浮层正文高度不应继续撑大，内容应可在正文区域内滚动查看和编辑，标题及关闭按钮保持可见。
- 画布节点提示词：图片等节点下方的提示词超过输入区域高度后，鼠标悬停在输入区域内滚动应查看提示词内容，不应缩放画布。
- 画布节点提示词回显：单图或多图生成完成后，切换选择生成结果的根节点及任一子节点，下方输入区域都应继续显示生成时的提示词；切换到其他节点再选回来后也不应清空。
- 画布生成配置：连接文本节点后连续点击生成（包含失败重试），组装提示词不应重复追加上游文本；在生图、文本、视频、音频之间切换时，实际请求应始终使用当前面板展示的对应类型模型。
- 画布左侧元素列表：点击元素整行应平滑定位并选中对应节点；有内容的图片元素应显示预览按钮，点击后打开大图弹窗且不触发画布定位。
- 配置与用户偏好：导出 JSON 后应包含渠道、默认模型、生成偏好、提示词来源和 WebDAV 配置；在修改当前配置后重新导入该文件，应恢复导出时的设置，错误 JSON 文件应提示格式不正确。配置文件包含 API Key 和 WebDAV 凭据，不应公开分享。
- 模型渠道协议：渠道编辑可选择「火山方舟」，切换协议时不得自动填入任何服务地址；用户手动配置后，任意名称的生图模型应按方舟 JSON 格式提交参考图，任意名称的视频模型应按方舟任务格式提交和查询，不再依赖模型名包含 `doubao`、`seedream` 或 `seedance`；1080p 不应再因模型名包含 `fast` 被禁用，参考视频应允许最大 200MB、总像素 409600-8295044，并继续校验官方宽高、比例和时长限制。
- 图片编辑弹窗：遮罩、切图和裁剪连续滚轮缩放时，图片与遮罩应保持同步且不再闪烁、短暂消失或跳动；遮罩画笔圆心应始终固定在鼠标位置，仅直径随缩放变化，缩放后仍可准确涂抹、拖动切分线和调整裁剪框。
- 提示词中心布局：页面标题及提示词总数应居中；连续输入搜索文字时应在停止输入约 300ms 后再查询；桌面端分类与标签应在左侧独立滚动，右侧搜索框下直接展示提示词卡片；标签数量较多时不能继续向下挤压提示词，窄屏下应恢复上下排列且内容不溢出；不再显示「我的提示词」Tab，收藏提示词应直接加入我的资产。
- 提示词详情弹窗：封面和参考图应固定显示在上方，复制及加入资产操作栏固定在底部，只有中间的标签、描述及提示词内容区域可以滚动；弹窗宽高应受视口限制且不超出屏幕。
- 提示词来源：首次打开时来源列表应为空；添加标准 JSON URL 后应能查看内容并按 `tags` 筛选，填写非数组 JSON 或不可访问地址时应显示失败，并继续保留该自定义来源上一次成功缓存的内容。
- 提示词来源界面：来源应以卡片列表展示，启用开关位于左侧，数量、同步状态和上次成功时间作为次级信息显示，查看、拉取及自定义来源编辑/删除操作使用带文字按钮；底部定时拉取区域应保持独立边框布局。
- 画布提示词库：不应再显示「我的提示词」分组；不展开任何公共来源直接搜索其中的提示词，匹配项应自动显示；点击「插入画布」后应创建正文正确且标题保持为提示词标题的文本节点。
- 全站 Agent：`generation_get_status` 仅查询当前活动画布的生成节点，可按 `nodeIds` 过滤并返回等待、运行、成功或失败状态；不得再暴露或跳转到独立生图、视频工作台。
- 本地 Agent 多标签页隔离：同时打开两个不同画布并连接同一个 Agent，分别聚焦标签页后通过 MCP 读取和修改画布，操作应只落在当前聚焦页面；网页面板发起的整个 Codex turn 应固定操作发起页面，即使中途聚焦另一标签页也不能切换目标；非运行状态关闭当前页面后应回退到最近聚焦且仍连接的页面，运行中关闭发起页面则不得把操作转交其他画布，只有同一页面身份重连后才能继续；其他页面回传同一请求结果应被拒绝。
- 本地 Agent 多标签页会话同步：所有标签页共享同一个站点级 Codex 活跃线程；任一页面发送消息、新建、恢复或删除会话后，其他页面应同步活跃线程和聊天记录；Agent 输出仅显示在事件所属线程，运行中不能新建、恢复、删除或再次发送任务。
- 本地 Agent 运行状态同步：在一个标签页运行较长 Codex 任务，等待某张工具卡显示「工具完成」后再打开或刷新第二个标签页；第二个标签页应立即显示 Codex 正在运行并禁用发送，整轮结束后两个标签页同时恢复；工具卡只显示「工具完成」，整轮结束由「本轮完成」表示。
- 本地 Agent 图片附件落画布：在右侧 Agent 上传参考图并要求基于商品信息创建生图流程，附件应创建为保持原比例的真实图片节点，分析提示词应创建为文本节点，二者都应连接到生成配置节点；刷新页面后参考图仍可显示并参与生成。任务中途切换到其他标签页时，附件只能写入发起任务的标签页；若发起标签页关闭，附件读取应失败且不能落入其他画布。
- Agent 对话滚动：从历史或日志切回对话、恢复其他会话时应自动定位到最新消息；手动向上浏览后应显示与日志完全相同尺寸、位置和样式的居中圆形向下箭头，新消息不强制打断阅读，对话底部不应出现额外留白，点击按钮后平滑回到底部并继续跟随新消息。
- Agent 消息区分：用户消息应在右侧使用透明无气泡排版，AI 回复应在左侧使用无头像的开放式 Markdown 排版；长文本、多张附件、错误消息及浅色/深色主题下均应清晰且不溢出。
- Agent 命令记录：命令执行中应显示运行状态；完成后，同一轮相邻命令应合并为「已执行 N 条命令」折叠行且默认不显示原始命令，单条展开后直接显示完整详情，多条展开后可分别查看命令、输出和退出状态；对话结束或刷新后分组与记录不应消失。
- 画布视频合成节点（仅桌面端）：工具栏或右键新建「合成」节点，把多个视频节点连到「片段」端口、一个音频节点连到「音乐」端口；面板中调整每段截取起止（含超出素材时长的钳制）、片段音量、背景音乐音量与淡出秒数、输出分辨率（长边 1080/720/480，画幅跟随第一段）、帧率与整体淡入淡出；点击「开始合成」后应显示运行态并在右侧生成新的视频节点，播放成片验证拼接顺序、截取范围、各段音量、音乐混音与淡出正确，失败时（如 FFmpeg 缺失、素材无本地文件）节点进入错误态并给出可理解的中文原因。
- 本地 FFmpeg 配置：设置页「本地 FFmpeg」小节仅桌面端可见；留空保存应回退到自动探测（PATH 及 C:\ffmpeg、C:\MediaToolkit、ComfyUI 整合包等常见目录），手动指定 ffmpeg.exe 完整路径后「检测」应返回实际找到的路径，路径错误时合成应报「未检测到可用的 FFmpeg」并引导打开设置；合成不随安装包分发 FFmpeg，卸载重装不应携带。

- 画布左侧工具栏：鼠标悬停任意工具图标应出现旋转并呼吸的彩虹光环，图标在彩色背景上保持清晰。
- 窗口顶部图标（下载目录、切换语言、返回、Agent）：悬停提示应向下弹出并完整可见，不再被窗口边界裁切。
