# 时间线与成片剪辑方案

本方案把「合成节点」从当前 MVP 扩展到可用的成片剪辑能力。目标不是做成专业 NLE，而是覆盖竖屏短剧与宣传片的真实需求：**片段之间要能转场、台词要能上字幕、人声和配乐要能分开调**。

## 现状（MVP）

`web/src-tauri/src/ffmpeg_compose.rs` 已经做到：

- 多个片段**顺序拼接**：`concat=n=N:v=1:a=1`，每个片段可单独裁剪，片段自身带淡入淡出。
- 成片整体**淡入淡出**。
- **一条**背景音乐轨：与拼接出来的原声用 `amix=inputs=2:duration=first,volume=2` 混合。

也就是说：能拼、能剪、能加一条背景音乐、能整体淡入淡出；不能转场、不能上字幕、不能分轨调音量。

## 阶段 1：片段之间的转场

**问题**：现在片段之间是硬切，短剧里最需要的「交叉溶解」没有。

**做法**：拼接阶段改用 FFmpeg 的 `xfade` 做视频、`acrossfade` 做音频，逐对串联：

```text
[0:v][1:v]xfade=transition=fade:duration=D:offset=T01[x1];
[x1][2:v]xfade=transition=fade:duration=D:offset=T02[x2];
```

`offset` 必须按前面所有片段已消耗的时长累加，并且每加一次转场总时长就减少 `D` 秒；音频轨用同样偏移的 `acrossfade`。转场类型先支持 `fade`（交叉溶解）、`wipeleft`、`slideup` 三种，时长 0.2–1.5 秒。

**UI**：合成节点里两个片段之间出现一个小圆点，点开选转场类型与时长；未设置时保持硬切。

**验收**：两段视频设 0.5 秒交叉溶解，成片在接缝处应看到画面叠加、总时长等于两段之和减 0.5 秒，且音轨不出现爆音。

## 阶段 2：字幕（台词烧进成片）

**问题**：台词现在只在音频节点里，成片看不到字。

**做法**：由音频/文本节点按时间轴生成一份 `.srt`，再用 `subtitles` 滤镜烧进成片，样式走 `force_style`（字号、描边、底部安全边距）。中文必须显式指定字体文件，Windows 上用系统自带字体路径（例如 `C:\Windows\Fonts\msyh.ttc`），避免 FFmpeg 默认字体渲染成方块。

- 字幕文本来源：优先取音频节点/文本节点里已经写好的台词，按片段时长顺序排布。
- 样式先给两套：**底部白字黑描边**（通用）与**居中大字**（短视频）。

**验收**：中文字幕在 Windows 上不乱码、不出现方块；长句自动换行且不出安全边距。

## 阶段 3：多轨音频（人声与配乐分开调）

**问题**：现在只有一条音乐轨，配音和配乐无法各自调音量，配音会被音乐盖住。

**做法**：把音频从「一条 music」改为**轨道列表**（人声轨 / 音乐轨 / 音效轨），每轨各自的音量、淡入、淡出与是否循环；用 `amix` 汇总时按轨数计算归一化，或改用 `volume` + `amix=normalize=0` 精确控制。旧请求结构直接按新设计替换，不做兼容。

**UI**：合成节点里每轨一行，含音量滑块与淡入淡出输入。

**验收**：同一段片子里人声清晰可辨、配乐可独立调到 0，混音后不削波。

## 阶段 4：时间线 UI

**问题**：片段多了以后，列表式面板看不清先后与时长比例。

**做法**：合成节点内提供横向时间线：片段按真实时长比例排布，可拖动换序、可拖两端裁剪，转场显示在两个片段之间，音频轨显示在下方。缩放档位给 3 档即可，不追求毫秒级精度。

**验收**：六个片段的合成里，拖动换序后成片顺序随之改变；裁剪手柄拖动后成片时长同步变化。

## 实施顺序与理由

| 顺序 | 阶段 | 理由 |
| --- | --- | --- |
| 1 | 转场 | 只改 FFmpeg 滤镜链与一处 UI，见效最快，且是「像成片」的关键 |
| 2 | 字幕 | 竖屏短剧的刚需，依赖音频/文本节点已有的台词 |
| 3 | 多轨音频 | 把已经能生成的配音与配乐真正用起来 |
| 4 | 时间线 UI | 前三项稳定后，再把它统一到一个直观界面上 |

每个阶段都按项目惯例走「提交 → 打包 → 安装 → 待测试 → 用户确认」的流程，确认后才写进正式功能说明。
